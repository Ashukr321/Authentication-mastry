How to read it

  1. Every successful login creates a new session row for that device.
  2. The yellow boxes are side effects: an alert for an unknown device, and the device limit.
  3. At the limit, the device used least recently goes, not the one created first.
  4. The access token carries the session id as sid, so this device can be revoked on its own later.

2. Data flow

Rahul is logged in on a laptop, a phone and a tablet. From the laptop he opens "Your devices" and logs out the tablet.

sequenceDiagram
    autonumber
    participant L as Laptop
    participant T as Tablet
    participant S as Server
    participant DB as Sessions + revoked list

    Note over L,T: earlier: 3 logins → 3 session rows (laptop 2418…, phone 68d0…, tablet 6e5d…)
    L->>S: GET /sessions (Bearer, sid 2418…)
    S->>DB: rows where userId = Rahul
    S-->>L: devices: tablet, phone, laptop (current: true)
    L->>S: DELETE /sessions/6e5d… (Bearer, sid 2418…)
    S->>DB: row 6e5d… belongs to Rahul ✓
    S->>DB: DELETE row 6e5d…, revoked[6e5d…] for 15 min
    S-->>L: 200 Logged out "Chrome on Android tablet"
    T->>S: GET /me (Bearer, sid 6e5d…)
    S->>DB: 6e5d… is revoked
    S-->>T: 401 session_revoked
    T->>S: POST /auth/refresh (cookie)
    S->>DB: no row with this refresh token hash
    S-->>T: 401 This device is logged out
    Note over L: the laptop and the phone keep working

How to read it

  1. Each column is one part of the system. Solid arrows are requests, dashed arrows are replies.
  2. Steps 1–3: "Your devices" lists the rows. current comes from the sid in the caller's token.
  3. Steps 4–7: the owner check, then two things: the row is deleted and the sid goes on the revoked list.
  4. Steps 8–10: the tablet's access token fails right away, not after 15 minutes.
  5. Steps 11–13: the tablet can't refresh either, so it must log in again.

3. How the pieces connect

One session row per device. The refresh token and every access token point back to it.

flowchart TD
    E(["Event"]) --> A1["Log out this device:<br/>revoke my sid"]
    E --> A2["DELETE /sessions/:id:<br/>revoke one, if it's mine"]
    E --> A3["Log out other devices:<br/>revoke all except my sid"]
    E --> A4["Password change / reset:<br/>revoke all (maybe keep mine)"]

Revoking a session = delete the row (the refresh token dies) + put its sid on a revoked list for one access token lifetime (its access tokens die). The table is touched at login, refresh and logout, not on every request.
