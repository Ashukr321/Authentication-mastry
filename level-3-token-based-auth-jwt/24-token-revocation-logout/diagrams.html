1. Flow diagram

The checks on every protected request. The last two are the price of revocation.

Accepted 401 State lookup (Redis / cache) 
flowchart TD
    A(["GET /me<br/>Authorization: Bearer eyJ…"]) --> S{"Signature valid<br/>(HS256 only)?"}
    S -- No --> E1[/"401 invalid_token"/]
    S -- Yes --> X{"exp in the future?"}
    X -- No --> E2[/"401 token_expired<br/>client refreshes (topic 22)"/]
    X -- Yes --> D{"jti on the<br/>deny-list?"}
    D -- "Yes: logged out<br/>on this device" --> E3[/"401 token_revoked"/]
    D -- No --> V{"ver = user's<br/>tokenVersion?"}
    V -- "No: logged out everywhere,<br/>password changed, banned" --> E3
    V -- Yes --> OK[/"200 request handled"/]

    classDef error fill:#fee2e2,stroke:#dc2626,color:#7f1d1d
    classDef ok fill:#dcfce7,stroke:#16a34a,color:#14532d
    classDef trap fill:#fef9c3,stroke:#ca8a04,color:#713f12
    class E1,E2,E3 error
    class OK ok
    class D,V trap

How to read it

  1. The first two checks are pure JWT: no database, no network.
  2. The yellow checks add state: a small set of revoked jtis and one number per user.
  3. The deny-list kills one token. A tokenVersion bump kills all of a user's tokens.
  4. Without the yellow checks, a logged-out token works until exp. That's fine only if tokens are very short.

2. Data flow

Rahul logs out on his laptop, his phone keeps working, then he clicks "log out everywhere" from the phone.

sequenceDiagram
    autonumber
    participant L as Rahul's laptop
    participant P as Rahul's phone
    participant S as Server
    participant R as Store (Redis / DB)

    Note over L,P: both logged in, tokens carry ver: 1
    L->>S: POST /auth/logout (refresh cookie + Bearer jti 3d54…)
    S->>R: DELETE laptop refresh token
    S->>R: SET deny 3d54… until its exp
    S-->>L: 200 Logged out on this device + cookie cleared
    L->>S: GET /me (Bearer jti 3d54…)
    S->>R: 3d54… is denied
    S-->>L: 401 token_revoked
    P->>S: GET /me (Bearer jti 3fb6…, ver 1)
    S-->>P: 200 phone not affected
    P->>S: POST /auth/logout-all
    S->>R: tokenVersion 1 → 2, DELETE all refresh tokens
    S-->>P: 200 Logged out on every device
    P->>S: GET /me (Bearer ver 1)
    S-->>P: 401 token_revoked (ver 1 ≠ 2)

How to read it

  1. Each column is one part of the system. Solid arrows are requests, dashed arrows are replies.
  2. Steps 1–4: logout revokes both tokens of this device: the refresh row is deleted, the access token's jti is denied.
  3. Steps 5–7: the laptop's token fails immediately, not after 15 minutes.
  4. Steps 8–9: the phone has its own jti, so it keeps working.
  5. Steps 10–14: one number bump revokes every access token of the user, on every device.

3. Which tool for which job

Pick the cheapest tool that is fast enough for the event.

No per-request lookup Needs a lookup on every request 
flowchart TD
    A1(["Logout on<br/>this device"]) --> B1["Delete its<br/>refresh token"]
    B1 --> C1{"Is up to 15 min<br/>of access OK?"}
    C1 -- Yes --> D1[/"Done: short TTL<br/>does the rest"/]
    C1 -- No --> E1[/"Deny-list the jti<br/>until its exp"/]

Every service that accepts the JWT must run the same checks (usually a shared Redis or the API gateway). If you end up with a lookup on every request anyway, compare with plain sessions (topic 09).
