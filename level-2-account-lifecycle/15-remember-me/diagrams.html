How to read it

  1. The session is always checked first. The remember-me cookie only matters when there's no valid session.
  2. The selector finds the row. The validator is the secret, compared by its hash.
  3. The yellow box: every use gets a new validator, so only one cookie is valid at a time.
  4. A known selector with an old validator means the cookie was copied → log out everywhere.
  5. A session started by remember-me is marked, so payment and security pages ask for the password again.

2. Data flow

Rahul ticks "Remember me". Later his session has ended, and he's logged back in. Then Priya tries a copy of his old cookie.

sequenceDiagram
    autonumber
    participant B as Rahul's laptop
    actor A as Priya (copied cookie)
    participant S as Server
    participant DB as Database

    B->>S: POST /login { email, password, rememberMe: true }
    S->>DB: INSERT session sha256("db23…") (30 min)
    S->>DB: INSERT remember "b074…" → { u_1, sha256("d744…"), +30 days }
    S-->>B: 200 + sid=db23… (no Max-Age) + remember=b074….d744… (Max-Age 30 days)
    Note over A: Priya copies remember=b074….d744…
    Note over B,S: 30 minutes later: the session has expired
    B->>S: GET /me (sid=db23…, remember=b074….d744…)
    S->>DB: session expired, find remember "b074…", hash matches ✓
    S->>DB: UPDATE "b074…" SET validatorHash = sha256("fce0…")
    S->>DB: INSERT session sha256("b88f…") { viaRememberMe: true }
    S-->>B: 200 { loggedInVia: "remember-me" } + remember=b074….fce0… + sid=b88f…
    B->>S: GET /payment-methods
    S-->>B: 403 Please log in with your password again
    A->>S: GET /me (remember=b074….d744…)
    S->>DB: find "b074…": sha256("d744…") ≠ stored hash 🚨
    S->>DB: DELETE all sessions and remember tokens of u_1
    S-->>A: 401 Your login may have been stolen
    B->>S: GET /me (sid=b88f…)
    S-->>B: 401 Rahul must log in with his password again

How to read it

  1. Each column is one part of the system. Solid arrows are requests, dashed arrows are replies.
  2. Steps 1–4: login creates two things: a short session and a 30-day remember-me token. Only hashes go into the database.
  3. Steps 5–9: the session has expired, so the remember-me cookie is used. The validator is replaced (d744 → fce0) and a new session starts.
  4. Steps 10–11: a remembered session can't open sensitive pages.
  5. Steps 12–15: Priya's copy has the old validator → theft detected → everyone is logged out, Rahul included (steps 16–17).

3. Session vs remember-me: two cookies, two jobs

The powerful cookie stays short-lived. The long-lived cookie can only start a new, less-trusted session.

Can do everything Limited: sensitive pages ask for the password
