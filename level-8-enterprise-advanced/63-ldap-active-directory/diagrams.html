1. Flow diagram

The safe POST /login in ChaiPortal: search, then bind, then groups. Each check stops one real attack.

Logged in Rejected The trap this check prevents 
flowchart TD
    A(["username + password"]) --> B{"Password empty?<br/>Username not a-z 0-9 . _ -?"}
    B -- Yes --> E1[/"400"/]
    B -. "skipping this" .-> T1[/"Empty password = unauthenticated bind:<br/>AD says success as anonymous"/]
    B -- No --> C{"3 failures for this<br/>username in 15 min?"}
    C -- Yes --> E2[/"429, before AD locks at 5"/]
    C -- No --> D["Service account searches OU=People<br/>(sAMAccountName=escaped input)"]
    D --> F{"Exactly one entry?"}
    F -- "0 or 2+" --> E3[/"401 Wrong username or password"/]
    F -- Yes --> G["NEW ldaps connection:<br/>bind as the user's DN + password"]
    G -- "error 49 (52e, 533, 775)" --> E3
    G -- ok --> H["Walk nested groups,<br/>map group DNs to roles"]
    H --> I{"In Portal-Users?"}
    I -- No --> E4[/"403 not allowed in this app"/]
    I -- Yes --> J["JIT local user by objectGUID,<br/>app session cookie"]
    J --> OK[/"Logged in with roles"/]

    classDef error fill:#fee2e2,stroke:#dc2626,color:#7f1d1d
    classDef ok fill:#dcfce7,stroke:#16a34a,color:#14532d
    classDef trap fill:#fef9c3,stroke:#ca8a04,color:#713f12
    class E1,E2,E3,E4 error
    class T1 trap
    class OK ok

How to read it

  1. The app never checks the password itself. It asks AD by binding as the user.
  2. The first check exists only because of the yellow trap: an empty password "succeeds".
  3. The service account searches, because AD refuses anonymous searches and because we need the user's DN and groups.
  4. Every failure after validation looks the same: 401 Wrong username or password. The AD data code goes to the log.
  5. A correct password is not enough: Neha has one but no Portal-Users group, so she gets 403.

Our limit (3) is below AD's lockout (5). Otherwise anyone can lock employees out of their laptops through our form.

2. Data flow

The real messages for Priya's login, from the test run on port 3063. Plain ldap:// would send her password in clear text; we use ldaps://.

sequenceDiagram
    autonumber
    actor P as Priya (browser)
    participant A as ChaiPortal (localhost:3063)
    participant D as AD dc1.chaicorp.local:636

    Note over A,D: at startup, over TLS
    A->>D: Bind CN=svc-chaiportal,OU=Service Accounts + its password
    D-->>A: success (service connection, reused)
    P->>A: POST /login { username: Priya, password: masala-dosa-77 }
    Note over A: lowercase, allowlist check, password not empty, under 3 failures
    A->>D: Search base OU=People filter (&(objectClass=user)(sAMAccountName=priya)) attrs cn, objectGUID, memberOf, sizeLimit 2
    D-->>A: 1 entry: CN=Priya Sharma,OU=People, memberOf IT-Leads
    A->>D: NEW connection: Bind CN=Priya Sharma,OU=People + masala-dosa-77
    D-->>A: success (AD checked the password)
    A->>D: Search base CN=IT-Leads scope base, read memberOf
    D-->>A: memberOf CN=Portal-Admins
    A->>D: Search base CN=Portal-Admins scope base, read memberOf
    D-->>A: memberOf CN=Portal-Users
    Note over A: roles = user, admin. JIT: create local user for this objectGUID
    A-->>P: 200 Welcome, Priya Sharma, roles user + admin, sid cookie (HttpOnly, SameSite=Lax)
    P->>A: GET /admin (cookie sid)
    A->>D: Search (objectGUID=Priya's) read userAccountControl
    D-->>A: 512 (enabled)
    A-->>P: 200 Admin panel
    Note over D: IT disables Priya: userAccountControl = 514
    P->>A: GET /me (cookie sid)
    A->>D: Search (objectGUID=Priya's) read userAccountControl
    D-->>A: 514 (disabled)
    A-->>P: 401 Your account was disabled or removed

How to read it

  1. Each column is one party. Solid arrows are requests, dashed arrows are replies.
  2. Steps 1–2: the app logs in to AD as itself once, over TLS.
  3. Steps 4–5: search finds Priya's DN and direct group. The input was escaped (here it has no special characters).
  4. Steps 6–7: bind as Priya on a new connection. This is the actual password check.
  5. Steps 8–11: follow nested groups up to Portal-Users. Step 12: our own session cookie.
  6. Steps 13–20: each request re-checks that the AD account is still enabled, so disabling her in AD ends her session.

How to read it

  1. Arrows mean "is a member of". Read from the bottom up.
  2. Priya → IT-Leads → Portal-Admins → Portal-Users, so she gets user and admin.
  3. Rahul → Engineering → Portal-Users, so he gets user only.
  4. Neha's Finance group isn't inside Portal-Users: right password, no access.

Match roles on the full DN (CN=Portal-Admins,OU=Groups,DC=chaicorp,DC=local), never on the name alone. AD can also resolve the chain in one search with the rule 1.2.840.113556.1.4.1941.

4. LDAP injection

The same search box input, Priya*)(salary=2*, glued into the filter vs escaped.

Input became filter code Input stayed data 
flowchart TD
    A1(["q = Priya*)(salary=2*"]) --> F1["(&(objectClass=user)(cn=Priya*)(salary=2*))"]
    F1 --> R1{"Any result?"}
    R1 -- "1 entry" --> L1[/"Salary starts with 2.<br/>Try 20*, 21*, … next digit"/]
    R1 -- "[]" --> L2[/"Not 2, try the next digit"/]
    L1 --> W[/"About 45 requests:<br/>2475000"/]

    classDef error fill:#fee2e2,stroke:#dc2626,color:#7f1d1d
    class F1,L1,L2,W error

flowchart TD
    A2(["q = Priya*)(salary=2*"]) --> E["escapeFilter:<br/>* to \2a, ( to \28, ) to \29"]
    E --> F2["(cn=Priya\2a\29\28salary=2\2a*)<br/>one condition on cn"]
    F2 --> R2[/"No name looks like that: []<br/>nothing to learn"/]

    classDef ok fill:#dcfce7,stroke:#16a34a,color:#14532d
    class E,F2,R2 ok

How to read it

  1. Left: the )( in the input closes the cn condition and opens a new one on salary. The app never returns salary, but "1 result vs 0" answers yes/no questions about it.
  2. Right: after escaping, the brackets and stars are plain characters inside one cn value. Our own trailing * still gives "starts with" search.
  3. Same idea as SQL injection: input is data, never filter code.

Also limit the damage: search only OU=People, ask for only public attributes, require login, and give the service account read access only to what the app needs.
