1. Flow diagram

One refund request: load the order, collect the attributes, then let decide() answer.

Allowed 401 / 403 Where beginners slip 
flowchart TD
    A(["POST /orders/ord_1/refund<br/>Bearer Priya's token"]) --> AU{"Logged in?"}
    AU -- No --> U[/"401 Please log in"/]
    AU -- Yes --> LD["Load the order FIRST<br/>(404 if it doesn't exist)"]
    LD --> AT["Collect attributes from the SERVER<br/>subject: support, Mumbai, limit 5000<br/>resource: Mumbai, 240, no legal hold<br/>action: order:refund<br/>env: hour 11 (server clock)"]
    AT --> D{"Any matching<br/>DENY policy?"}
    D -- "Yes: legal hold" --> F[/"403<br/>+ log: denied by no-refund-on-legal-hold"/]
    D -- No --> AL{"Any matching<br/>ALLOW policy?"}
    AL -- "No: other city, over limit,<br/>after 6 pm, not support" --> F2[/"403<br/>+ log: default deny"/]
    AL -- Yes --> OK[/"✅ refund runs<br/>+ log: allowed by policy id"/]

How to read it

  1. ABAC needs the resource's attributes, so the order is loaded before deciding.
  2. Every attribute comes from the server: the database for user and order, the server clock for the hour. Never from the request body.
  3. Deny is checked first: one matching deny beats any number of allows.
  4. If nothing allows it, the answer is no (default deny).
  5. Each decision is logged with the policy id that made it.

Different people, different orders, different times: the same decide() gives different answers.

    PDP-->>API: deny (outside 9 to 18)
    API-->>P: 403

How to read it

  1. Each column is one part of the system. Solid arrows are requests, dashed arrows are replies.
  2. Steps 1–8: same role, same order, different region attribute. Priya is refused, Arjun is allowed.
  3. Steps 9–14: the amount attribute. Over ₹5,000 needs a manager.
  4. Steps 15–17: even the manager's allow loses to the legal hold deny.
  5. Steps 18–20: the environment attribute. The same refund that works at 11:00 fails at 22:00.

In bigger systems the PDP is a separate service such as OPA or AWS Cedar, and the PAP is a Git repo of policy files. The shape stays the same: the app asks, the PDP answers, the app obeys.
