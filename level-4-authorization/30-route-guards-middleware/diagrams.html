1. Flow diagram

The middleware chain for DELETE /products/p_1. Each box can stop the request or pass it on.

Handler runs Stopped Where beginners slip 
flowchart TD
    A(["DELETE /products/p_1<br/>Authorization: Bearer token"]) --> J["express.json<br/>(400 bad JSON, 413 too big)"]
    J --> AU{"authenticate (global):<br/>token present?"}
    AU -- "No" --> ANON["req.user = null"]
    AU -- "Yes, but invalid" --> X401[/"401 Invalid or expired token"/]
    AU -- "Yes, valid" --> USER["req.user = Neha (editor)"]
    ANON --> M{"route matched?"}
    USER --> M
    M -- No --> N404[/"404 Not found"/]
    M -- Yes --> G1{"requireAuth:<br/>req.user set?"}
    G1 -- "No: return res.status(401)" --> L401[/"401 Please log in"/]
    G1 -- "Yes: return next()" --> G2{"requirePermission<br/>products:write?"}
    G2 -- "No: return res.status(403)" --> F403[/"403 + log"/]
    G2 -- "Yes: return next()" --> H[/"✅ handler deletes p_1, 204"/]
    F403 -. "forgot return: next() still runs" .-> BAD["handler runs anyway,<br/>p_1 deleted after a 403"]

How to read it

  1. authenticate runs for every request. No token means anonymous; a bad token is an error right away.
  2. The route's guards run in order. Each one either return next() or return res.status(...).
  3. The yellow box is the missing-return bug: the client is told 403, but the handler still runs.
  4. Anything that matches no route ends at the 404 handler; errors end at the error handler.

How to read it

  1. Each column is one part of the system. Solid arrows are requests or calls, dashed arrows are replies.
  2. Steps 1–5: the 403 is sent, but the guard doesn't return, so the handler deletes the product anyway.
  3. Steps 6–10: Express matches /BUGGY/ADMIN/secrets to the route, but the hand-written check doesn't. Fix: app.use("/admin", guard).
  4. Steps 11–14: a guard only protects routes registered after it. Fix: declare access per route, or put the guard first.

3. Structure

How the fixed app is put together. Every route sits under a guard, and a route without declared access stops the app from starting.

Public on purpose Guard Refused at startup 
flowchart LR
    REQ(["every request"]) --> AUTH["authenticate<br/>(global, sets req.user)"]
    AUTH --> PUB["'public'<br/>GET /health, POST /login,<br/>GET /products"]
    AUTH --> RA["requireAuth"]
    RA --> USERR["'user'<br/>GET /me"]

    RP --> PW["POST /products<br/>DELETE /products/:id"]
