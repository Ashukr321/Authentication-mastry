1. Flow diagram

What the server checks on every request to a protected page. With Basic Auth, there is no "already logged in": the full check runs every time.

flowchart TD
    A([Request to /admin]) --> B{"Has an Authorization header<br/>starting with Basic?"}
    B -- No --> E1[/"401 Unauthorized<br/>WWW-Authenticate: Basic realm=Admin area"/]

    G -- Yes --> H["Verify password against<br/>the user's stored hash"]

    H --> I{"Password<br/>matches?"}
    I -- No --> E2[/"401 Unauthorized<br/>Invalid username or password<br/>+ WWW-Authenticate"/]
    H2 --> E2

How to read it

  1. Start at the top: a request arrives for /admin.
  2. Diamonds are questions the server asks. Follow Yes or No.
  3. Red boxes send 401 with WWW-Authenticate, which makes the browser show its login popup.
  4. The yellow box hides which usernames exist (same as login in topic 07).
  5. The dashed arrow back to the top: the next request goes through all of this again.

Split at the first colon: usernames can't contain :, but passwords can, like priya:pass:with:colons.

2. Data flow

What travels between the user, browser, server and users store, from the first 401 challenge to the browser resending the password on every later request.

sequenceDiagram
    autonumber
    actor U as User
    participant B as Browser
    participant S as Server
    participant DB as Users store

    U->>B: Opens https://site.com/admin
    B->>S: GET /admin (no Authorization header)
    S-->>B: 401 Unauthorized<br/>WWW-Authenticate: Basic realm="Admin area"
    Note over B: Browser shows its built-in login popup
    U->>B: Types rahul / correct horse battery
    Note over B: Joins "rahul:correct horse battery"<br/>then Base64 → cmFodWw6Y29ycmVjdC...
    B->>S: GET /admin<br/>Authorization: Basic cmFodWw6Y29ycmVjdC...
    Note over S: Decode, then split at the first colon<br/>username "rahul", password "correct horse battery"
    S->>DB: Get the password hash for "rahul"
    DB-->>S: "a1b2…:9f8e…"
    Note over S: Hash the typed password and compare safely (~300 ms)
    S-->>B: 200 OK "Welcome to the admin area, rahul!"
    U->>B: Clicks another admin page
    B->>S: GET /admin/reports<br/>Authorization: Basic cmFodWw6Y29ycmVjdC... (sent again, automatically)
    Note over S: Decode + hash + compare AGAIN<br/>(every request costs ~300 ms)
    S-->>B: 200 OK
    Note over U,S: No session exists. The browser keeps sending the password<br/>until it is closed, so there is no real logout.

How to read it

  1. Each column is one part of the system.
  2. Solid arrows are requests, dashed arrows are replies.
  3. The numbers show the order things happen.
  4. Yellow notes are what the browser or server does on its own.
  5. Look for Authorization: Basic: it appears on every request after the popup.

cmFodWw6Y29ycmVjdCBob3JzZSBiYXR0ZXJ5 is only Base64. Anyone can decode it back to rahul:correct horse battery, so Basic Auth is only safe over HTTPS.
