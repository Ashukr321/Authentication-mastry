1. Flow diagram

What the server does when the user clicks "Log out": POST /logout

Success Refused: nothing changes Session deleted: every copy of the ID is dead Session store 
flowchart TD
    A(["User clicks Log out<br/>Cookie: sid=6ae3…"]) --> M{"Is it a POST?"}
    M -- "No: GET /logout" --> E1[/"405 Method Not Allowed<br/>Allow: POST"/]
    M -- Yes --> O{"Origin header is<br/>another site?"}
    O -- "Yes: evil.com" --> E2[/"403 Forbidden<br/>Request from another site was blocked"/]
    O -- "No (or no Origin)" --> C["key = sha256(cookie sid)"]
    C --> D[("Look up the key<br/>in the session store")]
    D --> F{"Session found?"}
    F -- Yes --> X["Delete the session<br/>on the server"]
    F -- "No: expired or<br/>already logged out" --> K
    X --> K["Clear the cookie<br/>same name + path + domain<br/>Expires=1970"]
    K --> S["Clear-Site-Data:<br/>cookies, storage"]
    S --> OK[/"200 OK<br/>Logged out"/]

How to read it

  1. Start at the top: the browser sends the logout request with its session cookie.
  2. Diamonds are questions the server asks. Follow the arrows.
  3. The two red boxes stop other sites from logging your users out: GET is refused, and so is a POST from another site's page.
  4. The yellow box is the real logout: once the session is deleted, a stolen copy of the ID stops working.
  5. "Session found? No" still ends in 200: logging out twice is not an error.

The cookie is cleared with the same options it was set with. A different Path would leave the real cookie behind.

2. Data flow

Rahul is logged in on a laptop and a phone. Priya copied the laptop's cookie. Watch what each logout does.

sequenceDiagram
    autonumber
    participant L as Rahul's laptop
    participant P as Rahul's phone
    actor A as Priya (stolen cookie)
    participant S as Server
    participant DB as Session store

    L->>S: POST /login { email, password }
    S->>DB: INSERT sha256("6ae3…") → { userId: "u_1", device: "Laptop" }
    S-->>L: 200 + Set-Cookie: sid=6ae3… (HttpOnly, SameSite=Lax)
    P->>S: POST /login { email, password }
    S->>DB: INSERT sha256("b71c…") → { userId: "u_1", device: "Phone" }
    S-->>P: 200 + Set-Cookie: sid=b71c…
    Note over A: Priya copies sid=6ae3… from the laptop
    L->>S: POST /logout (Cookie: sid=6ae3…)
    S->>DB: DELETE sha256("6ae3…")
    S-->>L: 200 + Set-Cookie: sid= (Expires=1970) + Clear-Site-Data
    A->>S: GET /me (Cookie: sid=6ae3…)
    S-->>A: 401 Not logged in ✓ (the server forgot it)
    P->>S: GET /me (Cookie: sid=b71c…)
    S-->>P: 200 still logged in (logout ends one device)
    P->>S: POST /logout-all
    S->>DB: DELETE every session WHERE userId = "u_1"
    S-->>P: 200 "Logged out of N device(s)"

How to read it

  1. Each column is one part of the system. Solid arrows are requests, dashed arrows are replies.
  2. Steps 1–6: each device gets its own session. The store keeps only the hash of each ID.
  3. Step 9: the laptop's session is deleted on the server. That's what kills Priya's copy in steps 11–12.
  4. Steps 13–14: the phone is untouched. A normal logout ends only this device.
  5. Steps 15–17: "log out everywhere" deletes every session of the user.
